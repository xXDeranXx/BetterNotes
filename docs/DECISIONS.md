# BetterNotes: decisions and history

The full, dated log of what was decided, measured, found and confirmed, milestone by milestone. It moved here from SPEC.md on 2026-10-23 to keep SPEC.md short. **Append new entries at the end of "Decided".** SPEC.md keeps only the rules future code must follow ("Rules learned"). Read the part of this file that belongs to the area you are changing (search for "M4," or "undo", for example), not all of it.

## Open questions
1. **M1, app language**: English (like the finance app) or German? Default: English.
2. **M1, minimum iPadOS**: which iPadOS version runs on the developer's iPad? Default: the current major version minus one, but at least 17.5 (squeeze).
3. **M2, tool picker**: start with the system `PKToolPicker` (all tools for free, less control over the look). Default: yes; a custom toolbar is under "Later".
4. **M6, export method**: (a) a `PDFAnnotation` subclass that draws each page's ink, written with `PDFDocument.write`, or (b) re-render every page with `UIGraphicsPDFRenderer`: the PDF page as vector, the ink as an image at 3× scale or more. Decide after testing both with a real lecture PDF (quality, file size, how it looks in Obsidian).

Decided:
- **M1, app language:** English only (no localization).
- **M1, minimum iPadOS:** 27.0 (the developer's iPad runs iPadOS 27; this is also Xcode 27's default target).
- **M1, Swift language mode:** Swift 6 (`SWIFT_VERSION = 6.0`). The project uses Xcode's default main-actor isolation, so file and model code that must run off the main thread is marked `nonisolated`.
- **M1, Info.plist:** a real `BetterNotes/Info.plist` (next to the `.xcodeproj`, outside the synchronized source folder) is merged with the generated one. It declares Files-app sharing, the `com.anvu.BetterNotes.inkbook` package type and PDF document types. Multiple windows are enabled with the build setting `INFOPLIST_KEY_UIApplicationSupportsMultipleScenes`.
- **M1, command line builds:** `xcode-select` points at the Command Line Tools, so use `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild ...`.
- **M2 spike, cancelling a stroke (2026-10-22, iPad with Apple Pencil): the live variant works.** A `UIGestureRecognizer` subclass that only listens (never recognizes, `state = .failed` on touch end) ran alongside PencilKit with a delegate returning `true` for `shouldRecognizeSimultaneouslyWith`. After 0.5 s with less than 4 pt of movement it toggled `canvas.drawingGestureRecognizer.isEnabled` to `false` and back to `true`. The half stroke disappeared cleanly: no flicker, no leftover ink, nothing committed to the drawing. M7 builds the live variant, not the fallback. Not yet checked: whether the Pencil can keep drawing right away after the cancel while still down (M7 draws the shape in the preview layer instead, so it does not depend on this). Also: a `PKCanvasView` must use `overrideUserInterfaceStyle = .light`, otherwise a black pen is drawn white on the white page in dark mode.
- **M2, overlay geometry (measured in the simulator with a real `PDFView` in a window):** the overlay PDFKit gives a page, and so its `PKCanvasView`, is always the size of the page in PDF points (595 x 842 for A4), at every zoom (1.4x, 2.7x, 5x). PDFKit enlarges it from outside. So ink coordinates are **page points, independent of zoom, origin at the top-left of the page, y pointing down** (UIKit view convention). PDFKit's own page coordinates (and SPEC's "File format" for objects) have the origin at the bottom-left with y up; the page renderer and the export flip y with `y' = pageHeight - y`. Milestone 2 step 5 turns this into the single tested conversion.
- **M2, canvas sharpness (measured, simulator, ~5x zoom):** `PKCanvasView` ignores `contentScaleFactor`; it draws ink at the resolution of its scroll view's `zoomScale`, and PDFKit enlarges the overlay from outside, so ink looked soft (edge softness 5.3 px). Fix: each visible canvas is made `k` times bigger (`bounds` x k), given `zoomScale = k`, and shrunk back with a `1/k` transform, where `k = min(max(1, ceil(pdfZoom)), 6)`. Edge softness drops to 1.3 px. Drawing coordinates stay in unzoomed page points; a stroke drawn while zoomed landed within 2 px of the touch points. The cap of 6 equals PDFView's maximum zoom; watch memory and heat on the iPad.
- **M2, tool picker appearance:** the picker follows the system appearance (the developer prefers the dark picker). Known quirk: in dark mode PencilKit shows its default black swatch as white while the ink on the white page is black. Forcing the picker to light (`toolPicker.overrideUserInterfaceStyle = .light`) removes the mismatch; offer it as a setting if it bothers the developer.
- **M2, coordinates and renderer:** `PageGeometry` is the single place for conversions: page coordinates (top-left origin, y down, in points; what ink, objects and shapes use) <-> PDF coordinates (bottom-left origin, y up, shifted by the display box's origin) <-> view coordinates (zoom and page offset). It is tested, and checked against a real `PDFView` at zooms 1, 2 and 4. `PageRenderer.render(page:drawing:scale:)` is the single page renderer (white page, PDF vector content, then ink; objects will go between in M8). `PKDrawing.image` adapts black ink to the current appearance, so the renderer always renders in the light appearance (a test fails if this is removed). Not yet verified: imported PDFs whose crop box does not start at (0, 0), and rotated pages; check both in M3 and M4.
- **M2, autosave:** `Notebook.saveChanges()` writes every changed page's drawing atomically on a background thread, then updates `meta.json` (`updatedAt`). It runs about 2 s after the last change (`autosaveDelay`), when a page's canvas leaves the screen, when the app leaves the foreground (with a background-task assertion), and when the notebook closes. Each page has a revision counter so a stroke added during a save is not marked as saved. A failed save keeps the page marked as changed, shows a banner with Retry, and the notebook refuses to close. A drawing file that cannot be read is copied to `<id>.drawing.unreadable` before it is replaced. `OpenNotebookRegistry` refuses to open the same notebook in two windows (bringing the existing window forward is M9). Loaded drawings stay in memory after their canvas is dropped; evicting saved, off-screen drawings is part of the M3 lazy-loading tuning.
- **M2, found by a force-quit UI test:** ink that was saved correctly did not show after reopening a notebook. Cause: the editor assigned the drawing to the canvas first and magnified the canvas (`zoomScale = k`, see "canvas sharpness") afterwards, and PencilKit does not redraw a drawing set before that change. Rule: a canvas gets its final size and zoom **before** it gets its drawing (`EditorCoordinator.overlayDidAppear`); a unit test with a spy delegate pins the order. Lesson: unit tests on the model were green while the real editor lost the ink, so keep an end-to-end check (draw, close or force-quit, reopen) for every change to canvas setup.
- **M2, heat safeguard:** `EditorCoordinator` watches `ProcessInfo.thermalState`. Canvas render scale is capped at 6 (nominal, fair), 2 (serious) and 1 (critical), applied to visible canvases at once and to pages that scroll in later, and restored when the iPad cools down. It is quiet (no message). Not yet measured on the iPad: whether the app gets warm at all; the developer will report after normal use. Future background work (thumbnails in M4, export in M6) should also pause or slow down at `.serious`.
- **Milestone 2 done (2026-10-22).** All six steps built; 81 unit tests pass (about 30 s) on the iPad Air 11-inch (M2) simulator. Device results from the developer's iPad: writing with the Pencil, finger scroll and zoom, palm rejection, undo, scrolling and the tool picker work; ink survives force-quit and reopen. Not yet confirmed on the device: ink sharpness after the zoomScale fix (the first fix did nothing; the second measured 1.3 px edge softness in the simulator) and whether the iPad gets warm (heat safeguard is in, see above). Temporary pieces to replace: the flat library list with "New Notebook" (M5), the `.pencilOnly`/`.anyInput` simulator switch is permanent. Known gaps: an unreadable drawing file shows a blank page without a message (the file is kept as `<id>.drawing.unreadable` on the next save); loaded drawings stay in memory (M3 tuning); two-finger tap undo and three-finger tap redo come in M7.
- **M3, import:** `NotebookPackage.importPDF` copies the PDF to `document.pdf` (the original is never touched) into a hidden staging folder, then renames it into place. The title is the file name without `.pdf`; the notebook opens at once (several PDFs: the last one opens). Password-protected, unreadable and zero-page PDFs are refused with a message and leave nothing behind. Entry points, all through `WindowSession.importPDFs`: the Files picker (`.fileImporter`), "Open in" and Files "Share" (`.onOpenURL` in `RootView`; imports into the window that received it, closing the open notebook there first), and drag and drop onto the library (`.onDrop(of: [.pdf])`). Window routing for "Open in" is M9.
- **M3, drag and drop (found on the iPad):** `dropDestination(for: URL.self)` did not work with Files. `onDrop` plus `loadFileRepresentation` does, but the temporary file is deleted when the callback returns, so it is copied at once into our own temp folder (keeping its name) and imported from there. A SwiftUI `List` swallowed drops inside its own area (the navigation bar accepted them, the rows did not), so the library list is a `ScrollView` with `LazyVStack`; build the M5 grid the same way and attach the drop handler to the scroll view.
- **M3, rotated and cropped PDF pages (measured in the simulator with a real `PDFView`):** `PDFPage.bounds(for:)` returns the page **before** its own `/Rotate`. For a page rotated by 90 or 270 PDFKit gives the overlay the *unrotated* size (595 x 842) and **turns the overlay itself** with a transform, so ink is stored in the unrotated page space and turns with the page on screen (ink stays on the same content). Consequences: `PageMeta.size` of an imported page is the *displayed* size (width and height swapped for 90 and 270; `rotation` holds the page's own `/Rotate`); `PageGeometry` keeps working with the unrotated crop box size; `PageRenderer` makes an image of the displayed size and turns the ink layer with the page (tested for 0, 90, 180, 270). Crop boxes with a non-zero origin work without changes (overlay and render are the crop box size). Not checked on a real rotated lecture PDF on the iPad.
- **M3, search:** `DocumentSearch` uses `PDFDocument.findString` (case and diacritics insensitive) and `PDFView.highlightedSelections` (yellow; the current match orange). It runs when Return is pressed (decided against live search); Return again goes to the next match, matches wrap around. PDFView does not redraw when only the colors of the same selection objects change, so the highlights are cleared and set again on every move. Only text that is part of the PDF is searchable, never handwriting.
- **M3, memory:** `Notebook.evictDrawings(keeping:)` drops a page's drawing from memory when it is off screen, saved (not in `dirtyPageIDs`) and was read without error; it runs after the save that follows a canvas leaving the screen. Unsaved, in-flight and unreadable drawings are never dropped. The 300-page open time (target under 2 s) and scrolling feel are **not measured on the iPad** (no large PDF available); an import of a generated 300-page PDF takes well under a second in the unit tests.
- **Milestone 3 done (2026-10-22).** Unit tests pass (107). Confirmed on the iPad by the developer: import from the Files picker, "Open in", drag and drop, writing on imported PDFs, search with highlights and next/previous. Not yet confirmed on the device: eviction on a long notebook (draw, scroll away, return, undo, force-quit) and a rotated or cropped PDF. Wishes noted for later: add PDFs and blank pages into an existing notebook (M4, "insert pages from another PDF"), horizontal page-by-page swiping (under "Later").
- **M4, page operations (model):** `Notebook` owns the one `PDFDocument`; the editor's `PDFView` shows that same object, so an operation shows on screen by itself (`onStructureChange` only asks the view to lay out again, needed for rotation). All operations live in `Notebook+Pages.swift` and change the PDF and `meta.pages` together through `setPageList`: insert (templates, pages of another PDF, an image), duplicate (copies the ink), delete (the last page cannot go; ink files stay on disk, undo restores the page with its ink), move, rotate (PDF `/Rotate`; ink turns with the page, see M3). Two mirror primitives (`insertEntries`, `removeEntries`) register each other as undo; one operation is one undo step. New pages take the size of the neighbouring page; the one-tap "add page at end" copies the last page's template (blank after an imported page). An image becomes a page A4 wide and as tall as the image needs; large photos are scaled down first.
- **M4, found by a test with a real `PDFView`:** PDFKit asks for a page's overlay **during** `document.insert(...)`, when the PDF already has the new page but `meta.pages` does not, so deriving a page's id from its index gave canvases the wrong page's ink. Rule: a page is identified by its `PDFPage` object (`Notebook.pageID(for:)`, a weak `NSMapTable` filled before the page enters the document), never by its position. Tests that show pages in a `PDFView` must give it `notebook.document`.
- **M4, saving two files as one:** `document.pdf` and `meta.json` are replaced together through `NotebookPackage.commitStructure`: both new files go into `pending/`, an empty `COMMIT` file is written last, then the files are moved over the old ones. `Notebook.open` first calls `finishPendingCommit`: a complete `pending/` is finished, an incomplete one (no `COMMIT`) is thrown away. Tested for a crash before the marker, after it, and between the two moves. Autosave saves a page change with the normal 2 s delay; while a page change is unsaved `meta.json` is never written alone, closing the notebook is refused (`hasUnsavedChanges`), and a failed save shows the usual banner with Retry. `PDFDocument.dataRepresentation()` runs on the main thread; on a generated 300-page text PDF a page operation plus save takes about 30 ms, but a PDF with many large images has **not been measured**: watch for a pause after page operations on image-heavy lecture PDFs.
- **M4, thumbnails and sidebar:** `ThumbnailStore` renders at scale 0.5 through `PageRenderer`, on the main thread one picture at a time (it yields in between and waits a second when the thermal state is serious), with a memory cache and JPEG files in `thumbnails/<id>-r<rotation>.jpg`. A picture is out of date when the page's ink changed (`Notebook.revisions`, now observable) or the page was turned; a file on disk is reused only if it is not older than the page's saved drawing file. Rendering a thumbnail evicts the page's drawing from memory again unless the page is on screen (`Notebook.visiblePageIDs`, set by the coordinator). The sidebar is a `ScrollView` + `LazyVStack` (not a `List`, see M3), with tap to jump, a long-press page menu (insert before/after with a template, duplicate, rotate, delete) and an add-page button (tap = like the last page, hold = choose the template).
- **M4, page grid:** a full-screen cover from the toolbar. Tap = go to the page, "Select" for multi-select (duplicate, rotate left/right, delete, insert, move or copy to a notebook), drag to reorder (`.draggable` with the page id as text, `.dropDestination(for: String.self)`; dragging a selected page moves the whole selection). Dropping onto a page puts the pages **before** it when dragging backward and **after** it when dragging forward (`PageReorder`, tested). The Pencil tool palette floats above everything in the window, so it is hidden while the grid is open (`setToolPickerHidden`).
- **M4, inserting from outside:** one shared modifier (`pageInsertion`) for the editor toolbar menu (new pages after the page on screen) and the grid (after the last selected page, else at the end): PDF from Files, photo (PhotosPicker) and image from Files. A single `fileImporter` serves PDFs and images (two on one view fight). Files are read completely into memory while the security-scoped access is open, so the inserted pages do not depend on the source file (tested: the source file is deleted before saving).
- **M4, move or copy to another notebook (`PageTransfer`):** checks first, then adds copies (new ids, ink included, also unsaved ink) at the end of the target and **saves and confirms** that, and only then removes the pages from the source for a move. Refused: the same notebook, a target open in another window (it would overwrite the change), moving every page, a target whose list and PDF disagree, a target that cannot be saved (the source stays untouched; tested with a mutation that deletes first). Undoing a move brings the pages back into the source; the copies in the target stay (a duplicate, never a loss).
- **Milestone 4 done (2026-10-23).** 173 unit tests pass (about 14 s) on the iPad Air 11-inch (M2) simulator. **Confirmed on the developer's iPad:** the sidebar, the grid, drag to reorder in both, the plus menu (templates and inserts), Change Template, and rotating a page without any jump. Everything else was checked with unit tests, a real-`PDFView` test and simulator screenshots. **Not yet confirmed on the iPad:** the Photos picker, move or copy to another notebook, and the whole flow "reorder pages with ink, undo, redo, force-quit, reopen"; and the save time after a page operation on an image-heavy PDF (about 30 ms on a generated 300-page text PDF). Known limits: the page-list undo history is not saved (after a restart "undo" cannot bring back a deleted page; its ink file is still in `drawings/`); orphaned drawing files of deleted pages are kept (cleaning up is a later, never automatic, tidy-up); inserting a whole PDF always inserts all of its pages (no page picker); no horizontal page-by-page mode yet (under "Later").
- **M4 polish after the first iPad test (2026-10-22/23):** the plus (sidebar and grid) opens a menu on tap: new page with Blank, Lined, Grid or Dotted at the end, and Insert (PDF, photo, image from Files); there is no add-page or insert button in the top bar, the grid button sits at the left next to the sidebar toggle, and the sidebar slides in and out. Pages can be dragged to reorder in the sidebar too (same `PageReorder` rule as the grid). Long-press on a page made from a template shows **Change Template** (not for imported PDF pages): `Notebook.changeTemplate` swaps the PDF page for a freshly generated one, keeping id, ink, displayed size and rotation, as one undo step; thumbnail key and cache file name now contain the template. Rotation preview: every thumbnail sits in a **fixed slot shaped like the page before its own rotation**, so turning a page changes no layout at all (a cell that changed shape was laid out at its new size at once while the picture animated, which made it jump up and back down; checked with a UI test that the neighbouring button does not move). Inside the slot the old picture is only scaled and rotated (never resized) and the sharp new picture replaces it after the 0.3 s turn, because replacing it earlier snapped the angle back mid-turn. A page turned sideways is therefore shown smaller, centred in its slot. Found with a screenshot: after turning a page sideways the editor kept the old fit-to-width zoom and the page ran off the screen, so `NotebookEditorViewController` fits again when a page operation changes the fit scale (and keeps the user's zoom otherwise). Animations themselves cannot be seen in simulator screenshots; judge them on the iPad.
- **M4, confirmed on the iPad (2026-10-23):** the Photos picker, move or copy to another notebook, the flow "reorder pages with ink, undo, redo, force-quit, reopen", ink sharpness after the zoomScale fix, and a real rotated PDF all work. **Heat is still unverified** (not enough use yet); keep the thermal safeguard and measure during normal use.
- **M5, library (foundation and UI built, 2026-10-23; iPad check pending):** `LibraryScanner` reads folders and notebooks (a notebook with a damaged `meta.json` is listed with a problem message and never hides the others); `LibraryOperations` does create folder, rename (title in `meta.json` and the `.inkbook` name), move, duplicate, cover color and trash. Name clashes get a number **in brackets**, "Name (2).inkbook" (also for new notebooks and imports). Nothing open in a window can be moved, renamed or trashed (`OpenNotebookRegistry.isOpen(at:)`, also for a folder that contains an open notebook). The trash keeps each item in `.Trash/<uuid>/` with an `origin.json` so "Put Back" returns it to its folder (or the root); items older than 30 days are purged on launch. `.library.json` holds favorites, recents (max 10) and the sort choice by notebook **id**, so a notebook moved in the Files app stays a favorite; a broken file falls back to defaults and is kept as `.library.json.unreadable`. UI, styled after Goodnotes: sidebar (Documents, Favorites, Recents, Trash), tile grid with first-page covers (`CoverStore`, cached in `thumbnails/cover.jpg`) and a colored spine, tap a folder to open it with a breadcrumb bar, search across all folders, sort menu, long-press menu (rename, duplicate, move to, favorite, cover color, trash), drag onto a folder or breadcrumb, "Move to..." picker, rescan when the app becomes active. The consistency check on open already existed (`Notebook.structureProblem`: read-only with a message). Not yet checked on the iPad: drag onto folders, trash and put back, moving a notebook in the Files app while the app is in the background, covers of imported PDFs.

Closing is an instant swap. **Confirmation dialogs must be attached to the button or tile they belong to**: on the iPad they are popovers that point at the view they are attached to, and attached to a whole screen they appeared in the sidebar. - **M6, export (built 2026-10-23; iPad check pending):** `NotebookExporter` writes a flattened PDF of all or chosen pages (document order) with **method (b)**: `UIGraphicsPDFRenderer`, each page drawn by `PageRenderer.draw` (now shared with `render`, so thumbnails and export cannot differ): the PDF page stays vector (text stays searchable, tested), ink is a bitmap at 4 px per point (`inkScale`, about 288 dpi), rotation is baked into the page. It runs off the main thread, can be cancelled, backs off at thermal `.serious`, and works from bytes, so the open notebook is not touched (tested). **Method (a) was probed, not chosen:** a `PDFAnnotation` subclass with custom `draw` does survive `PDFDocument.write` (the ink was visible after reading the file back), but the image came out mirrored vertically (PDF coordinates, y up), so it would need a flip. **Open: the size and sharpness comparison on a real lecture PDF with ink** (needs a file from the developer); until then (b) is in use, and (a) stays an option if (b)'s files are too big. Entry points: editor toolbar "Export PDF" and the library's long-press "Export PDF…" (a notebook open in a window is refused there), both open `ExportSheet`: all pages or **Choose Pages** (thumbnail grid with ticks), then **Share…** (share sheet) or **Save to "<folder>"** into the remembered export folder (`ExportFolderStore`: a bookmark in `UserDefaults`, because it belongs to the device; picked once with the Files picker, changeable). A taken file name gets a number, "Name (2).pdf", so a re-export never overwrites an older one (the developer may want "replace" for Obsidian; judge on the iPad).
- **M6, backup and sizes (built 2026-10-23):** the library shows the **size of every notebook and folder** (tiles and rows; `StorageSize`, measured in the background, without `thumbnails/` and the trash, so it is what a backup contains). `LibraryBackup.makeBackup` makes one ZIP with `NSFileCoordinator` `.forUploading`, from a staging folder of **hard links** (no extra space, falls back to copying), without `.Trash` and thumbnails; the temporary ZIP is moved out, not copied, so it exists only once. `BackupSheet` shows the size, the free space on the iPad and the last backup **before** anything is made, and refuses when there is not enough room; a folder can be backed up on its own (long-press, "Back Up…") for people with little space. A ZIP is about as big as the notebooks (PDFs and ink hardly compress). `lastBackup` is stored in `.library.json` when the share sheet reports success; a banner at the library root appears when it is missing or older than 14 days (dismiss with the x for the session). **Import Folder…** (the "+" menu) copies a picked folder (an unzipped backup) as one new folder, or a single `.inkbook` as a notebook, into the folder on screen through a hidden staging folder; a taken name gets "(2)", nothing is merged or overwritten, and a folder without notebooks is refused. Not done: restoring favorites and recents from a backup (they live in `.library.json` and are not merged), and a progress bar for the ZIP.

- **M7a, decisions before building (2026-10-23):** (1) **Dashed and dotted lines** are only for the line and shape tool, made of many short normal `PKStroke`s in one undo step (PencilKit has no dashed ink); freehand pens stay solid. The eraser removes single dashes, the lasso can select them together. (2) **Hold to smooth** a freehand stroke becomes a smooth fitted curve, and while the Pencil stays down, moving it bends the curve; it is built in **M7** together with shape recognition (live preview layer), not in 7a. - **Tabs, design (decided 2026-10-23, before building):**
  - **Background tabs keep their model and undo.** This changes the earlier rule "released down to title, scroll and zoom". The undo history lives in `Notebook.undoManager`, so releasing the model would lose undo on every tab switch. Heat comes from views (`PDFView`, canvases, rendering), not from the model: off-screen drawings are already evicted and `PDFDocument(url:)` loads lazily. So a background tab drops only the editor, `PDFView` and canvases.
  - **No tab limit**, like Goodnotes (which has no documented cap; users report 20 to 50 tabs, and only a few stay loaded). The **3 most recently used tabs** keep their model and undo (number to be measured with the debug overlay on the iPad). Older tabs are released down to URL, title, scroll position and zoom; they lose their undo history and reopen when tapped.
  - **Library**: a Home button shows the library. The tab strip stays and every tab stays open (saved, without views). Opening a notebook from the library makes a **new tab**; if the notebook is already a tab in this window, that tab is selected instead.
  - **Code changes**: `WindowSession` holds `tabs` plus an active id instead of one `notebook`. Switching saves the active tab first; a failed save stops the switch, as `close()` does. There is no library fade animation between tabs. Closing a tab saves first. `importPDFs` opens a new tab instead of closing the current notebook. `isolated deinit` releases every tab's claim. `OpenNotebookRegistry` records the owner (window and tab id), not only the URL, so M9's "bring its window forward" can bring the right window forward and select that tab. **A tab counts as open as long as it exists, even when released** (one notebook is in at most one tab of one window). The library still refuses to move, rename or trash it.
  - **Not now**: restoring tabs after a relaunch, and dragging tabs between windows. Tab state stays per window (architecture decision 5).
  - **Order**: debug overlay first (needed to measure memory and heat with tabs), then tabs, then M9 with bring-forward built on the new registry.
