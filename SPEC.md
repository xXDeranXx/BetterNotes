# Notes App: Spec

Working title: **Inkbook** (rename any time).

## Goal
A personal handwriting notes app for the iPad with the Apple Pencil Pro, replacing Goodnotes. It holds notebooks (blank, lined, grid or dotted pages) and imported PDFs (lecture slides, exercise sheets) in one format, lets the developer write and draw on every page, manage pages freely, organize everything in folders, and export finished notebooks as normal PDFs (for example into the Obsidian vault).

## Constraints
- **Native iPad app** in Swift. No web technologies: handwriting latency is the main quality goal, and only Apple's PencilKit reaches it.
- **iPad only**, landscape and portrait. No iPhone or Mac version.
- **No sync between devices, no handwriting search.** Both are out of scope (see "Out of scope").
- **Free Apple developer account** (personal team). Consequences that the design must respect:
  - The app is installed from Xcode and stops launching after 7 days until it is installed again. Reinstalling over the existing app **keeps all data**.
  - **Deleting the app from the iPad deletes all notebooks.** The app must make backups easy (milestone 6), and the README must warn about this.
  - No iCloud, no push notifications, no app groups. If a feature needs a paid account, flag it before building.
- **Apple frameworks only**: SwiftUI, UIKit (where SwiftUI has no equivalent), PencilKit, PDFKit, UniformTypeIdentifiers, PhotosUI, AVFoundation (later). No third-party dependencies unless discussed first.
- All data lives in the app's Documents folder and is **visible in the Files app**, so the developer can always copy it out by hand.
- The developer is a CS student who knows JavaScript and basic React but is **new to Swift, SwiftUI, UIKit, PencilKit and PDFKit**. Prefer readable, idiomatic code over clever code (the developer reviews everything the AI writes), and explain non-obvious concepts when introducing them.

3. Keep changes small and focused. One milestone = one or more git commits with clear messages.
4. **Never risk notebook data.** All writes are atomic; no code path deletes user files except the trash (see "Data safety"). Any migration of the file format keeps a copy of the old version until it succeeded.
5. Write tests for the logic layer (file format, page operations, template generation, shape recognition, export). UI tests are not required.
6. Things that only show on a real iPad with a Pencil (latency, palm rejection, coordinates while zooming, squeeze) cannot be verified in the simulator. Say so, and give the developer a short checklist to try on the device.
7. If something in this spec looks wrong, risky, or much harder than it reads, say so instead of silently working around it.

## Stack
- **Swift 6, SwiftUI** app lifecycle; UIKit views wrapped with `UIViewRepresentable` where needed (`PDFView`, `PKCanvasView`)
- **PDFKit**: `PDFView` shows every notebook; `PDFPageOverlayViewProvider` puts one `PKCanvasView` over each visible page
- **PencilKit**: ink, eraser, lasso, `PKToolPicker`
- **Swift Testing** (or XCTest) for unit tests
- Minimum iPadOS: see "Open questions" (squeeze needs iPadOS 17.5 or later)
- Xcode on the developer's Mac, git, GitHub

## Core idea: every notebook is a PDF
There is only one kind of document. A blank notebook is a PDF the app generates from page templates; an imported PDF is used as it is. Adding a page means inserting a page into the PDF. Ink is **never** written into the PDF while working; it is stored next to it and only merged on export. This keeps the original file untouched and all ink editable.

## File format
A notebook is a folder with the extension `.inkbook`, declared as an exported type that conforms to `com.apple.package`, so it looks like one file in the Files app.

```
Documents/
├── Uni/                          ← library folders are real folders
│   └── Analysis/
│       └── Lecture 3.inkbook/
│           ├── document.pdf      ← the pages (imported or generated)
│           ├── meta.json         ← see below
│           ├── drawings/
│           │   └── <pageID>.drawing   ← PKDrawing.dataRepresentation()
│           ├── objects/
│           │   └── <objectID>.png     ← inserted images
│           └── thumbnails/            ← cache, may be deleted any time
├── .Trash/                       ← deleted notebooks and folders
└── .library.json                 ← favorites, recents, sort choice
```

`meta.json`:
- `formatVersion` (starts at 1; any change to the format increases it and comes with a migration)
- `id`, `title`, `createdAt`, `updatedAt`, cover color
- `pages`: an ordered list, one entry per PDF page, **in the same order as the pages in `document.pdf`**: `id` (random UUID), `template` (`pdf` for imported pages, otherwise `blank`, `lined`, `grid`, `dotted`), page size, rotation
- `objects`: images and text boxes per page id, with position and size in **page coordinates** (points, origin as in PDFKit)

Rules:
- Ink and objects belong to a **page id, never a page number**. Reordering, inserting and deleting pages only changes the order of `pages` and of the pages in the PDF.
- On every open, the app checks that `pages` and `document.pdf` have the same count. If not, it repairs what it safely can, and otherwise opens the notebook read-only with a message. It never deletes drawings it cannot assign; it keeps them.
- Drawings are stored in page coordinates, so they stay in place at any zoom level and survive rotation.

## Data safety
- **Autosave**, never a Save button: a changed page's drawing is written about 2 seconds after the last stroke, when its overlay leaves the screen, when the notebook closes, and when the app goes to the background.
- Only changed files are written. `document.pdf` is rewritten only after page operations.
- Every write is **atomic** (write to a temporary file, then replace). A crash leaves either the old or the new file, never half of one.
- Deleting a notebook or folder moves it to `.Trash`. The trash can be emptied by hand and removes items older than 30 days.
- When the app returns to the foreground it rescans the library, because files can change in the Files app while it is in the background.
- A notebook is open in at most one window at a time. Opening it a second time brings the existing window to the front.

## Architecture decisions
These are fixed in milestones 1 and 2 so that later milestones add to the code instead of rewriting it. Changing one of them later needs a discussion first.

1. **Undo works on data, not on canvas objects.** Canvases are created and dropped while scrolling (lazy loading), so no undo step may point at a `PKCanvasView`. Each notebook window has one `UndoManager`; every undo step changes the notebook model (a page's `PKDrawing` by page id, the page list, an object), and visible canvases update from the model. PencilKit's own undo registration is turned off or replaced so that it never holds a canvas. Strokes (M2), page operations (M4), shapes (M7) and objects (M8) all use this one mechanism.
2. **One model, many views.** A `Notebook` model (pages, drawings by page id, objects) is the single source of truth while a notebook is open. Canvases, thumbnails, the page grid and export read from it; autosave writes it to disk.
3. **The page overlay is a layered container**, not a bare canvas: from bottom to top an objects layer (empty until M8), the `PKCanvasView`, and a preview layer (for live shapes in M7). Later features add content to a layer, not new view structure.
4. **One page renderer.** A single function renders a page (PDF page, objects, ink) at a given size. Thumbnails (M4) and export (M6) both use it, so anything new on a page (objects in M8) appears in both automatically.
5. **State per window.** The app supports multiple windows from milestone 1. The open notebook, its model, its `UndoManager` and the editor state belong to a window (scene), never to a global singleton. A notebook is open in at most one window (see "Data safety").
6. **Coordinates**: ink, objects and shapes are stored in page coordinates. Conversion between view and page coordinates lives in one place and is tested.

## Version 1 features

### 1. Writing
- **Goodnotes-style tools and customization** (Milestone 7a): a custom toolbar with several editable pens (fountain, ballpoint, brush-like, pencil), highlighter/marker, eraser, lasso, ruler, and shape tool; each pen has its own saved color and width, a row of favorite colors, a stroke preview, and the toolbar can be moved and collapsed. Built on PencilKit's `PKInkingTool` types; what PencilKit cannot do (for example custom brush textures) is listed in the milestone instead of faked.
- PencilKit ink with the system tool picker: pen, marker, pencil, eraser (stroke and pixel), lasso (move, resize, copy, paste, delete), ruler, colors and widths.
- **The Pencil writes, fingers scroll and zoom** (`drawingPolicy = .pencilOnly`). A setting allows finger drawing.
- **Undo and redo** for strokes, objects **and** page operations in one history per notebook window. Two-finger tap = undo, three-finger tap = redo (configurable).
- **Pencil Pro**: squeeze shows the tool palette near the Pencil; double tap follows the system setting (for example switch to the eraser).
- **Shape recognition while holding** (important to the developer): draw a line, rectangle, ellipse or triangle and hold the Pencil still for about 0.5 s **without lifting**. The stroke turns into a clean shape **immediately**, while the Pencil is still down, and keeps following the Pencil until it is lifted (a straight line can be lengthened and rotated, a shape resized). On lift the shape becomes a normal `PKStroke` in the same color and width, so eraser, lasso and undo work as usual. A setting turns it off.
  - PencilKit has no public API to change a stroke in progress. Planned approach:
    1. A custom gesture recognizer runs **simultaneously** with `PKCanvasView.drawingGestureRecognizer` and reads the Pencil's points live (page coordinates).
    2. A hold is detected when the Pencil stays within a few points for about 0.5 s; the points so far are classified as line, rectangle, ellipse or triangle (or nothing).
    3. The PencilKit stroke in progress is cancelled (for example by toggling `drawingGestureRecognizer.isEnabled`); **whether this discards the half stroke cleanly is verified by a spike in milestone 2**.
    4. A preview layer above the canvas draws the shape and follows the Pencil.
    5. On lift, a `PKStroke` built from the shape is added to the drawing and registered with the undo history.
  - **Fallback** if step 3 is not reliable: detection after the stroke ends, using the stroke's point time offsets to detect the hold at the end, and replacing the stroke. The classification code is the same in both variants.
- Vertical continuous scrolling through all pages.

### 2. Notebooks and PDFs
- New notebook: title, template (blank, lined, grid, dotted), size (A4 portrait default, A4 landscape), cover color.
- Templates are drawn as vector lines into the generated PDF pages, so exports show them.
- Import PDFs from the Files app, from the share sheet ("Open in Inkbook") and by drag and drop from another app in Split View.
- Imported PDFs: write on every page; PDF text search inside the open notebook (`PDFDocument.findString`), with results highlighted.
- Large PDFs (300+ pages) open in under 2 seconds; only visible pages have a canvas in memory.

### 3. Page management
- Page sidebar in the editor (thumbnails, tap to jump).
- Page grid view: select one or several pages; drag and drop to reorder.
- Insert a page before or after with a chosen template; add a page at the end with one tap.
- Duplicate, delete, rotate pages.
- Insert pages from another PDF; insert a photo or image file as a new page.
- Move or copy selected pages to another notebook.
- Page thumbnails show the page with its ink (rendered in the background and cached).
- All page operations can be undone.

### 4. Objects on pages
- **Images**: insert from Photos, Files or the clipboard; move, resize, delete.
- **Text boxes**: tap to place, type with the keyboard, move, resize, font size, delete.
- Objects lie **below** the ink, so ink can be written on top of them.
- PencilKit's lasso only selects ink. Objects are selected with a separate tap (or an "objects" mode); this limitation is accepted.

### 5. Library
- Nested folders: create, rename, move, delete (to trash). **Folder icons**: each folder can get a symbol (book, school, atom, ...) and a color, shown on a drawn folder icon.
- Notebooks: rename, move, duplicate, delete (to trash), change cover.
- Grid view with covers or first-page thumbnails; sort by name, date modified or date created.
- Favorites and "Recently opened".
- Search by notebook and folder title.

### 6. Export and backup
- Export a notebook (all pages or the selected pages) as a **flattened PDF**: original pages stay vector, ink is merged on top (method decided in milestone 6, see "Open questions").
- Share via the share sheet, or **save to a remembered export folder** (for example a folder in the Obsidian vault), stored as a bookmark so it needs no picker every time.
- **Library backup**: the whole Documents folder (without thumbnails) as one ZIP file through the share sheet, created with `NSFileCoordinator` (`.forUploading`), so no ZIP library is needed. Restore: unzip in the Files app and import the folder (an "Import folder" action in the library).
- A gentle reminder in the library when the last backup is older than 14 days.

### 7. Daily use
- **Multiple windows / Split View**: for example lecture slides on the left, own notebook on the right.
- Dark mode for the interface; pages stay white.
- Empty states, loading states, and error messages that say what happened and what to do; nothing is sent anywhere.

## Later, one at a time
- **Tabs like Goodnotes** (wish from the developer, 2026-10-23): several notebooks open as tabs in one window, switching with one tap. **Heat is the main constraint** (see "M2, heat safeguard"). Rules for the design: only the active tab has a `PDFView`, canvases and render work; a background tab is saved, then released down to its title, scroll position and zoom (reopening is fast because notebooks load lazily); never keep several `PDFView`s alive for instant switching; thumbnail and cover rendering pause while the thermal state is `.serious`; limit the number of open tabs (about 5) and measure temperature and memory on the iPad with 2, 3 and 5 tabs before settling the limit. It touches architecture decision 5 (today a `WindowSession` holds one notebook), so it needs a short design discussion first; a tab strip also fits next to multiple windows (M9) rather than replacing them. Open question for then: tabs inside a window and the "one notebook, one window" rule must agree (a tab counts as open).
- **Whiteboard / infinite canvas** (wish from the developer, 2026-10-23): a second kind of document without page borders, for brainstorming and diagrams. **It breaks the core idea "every notebook is a PDF"**, so it needs a design discussion before any code. Options to compare: (a) a notebook with one very large page (PDF pages stop at 14400 points, and one huge `PKCanvasView` costs a lot of memory and heat, so only for a bounded board); (b) a new document kind `whiteboard` in `meta.json` (format version bump with migration, see "File format") whose ink is stored in tiles (for example 2048 x 2048 point chunks, one `PKDrawing` file per tile that has ink), shown by an own `UIScrollView` with a `PKCanvasView` only for the visible tiles (the same lazy idea as pages), with export to PDF as the bounding box of the ink. Questions to settle: do tiles break strokes that cross a tile border (probably split them), what does undo see (the model, as everywhere), do images and text boxes (M8) work on it, and which of page management (M4) applies. Heat and memory are the main risks, as for tabs. Not before M8.
- **Scan documents** (wish, 2026-10-23): a "Scan Document" action in the library's "+" menu and in the page insert menu. Uses VisionKit's `VNDocumentCameraViewController` (Apple, free, needs a camera usage text `NSCameraUsageDescription` in `BetterNotes/Info.plist`; VisionKit is not on the framework list under "Constraints", so this entry is the discussion). Each scanned page is an image, so it reuses "image as a page" from M4 (a new notebook from the scan, or pages inserted after the current page). **Compression** (decided 2026-10-23): a camera scan is a photo of about 12 megapixels, and every page operation rewrites the whole `document.pdf` (see M4, save time on image-heavy PDFs, not yet measured), so scans are made small on purpose: shrink to about 200 dpi (1654 px wide for A4; the existing `makeImagePage` allows about 290 dpi), compress as JPEG at quality about 0.7, and make sure the PDF really embeds the JPEG (UIKit's PDF renderer does not guarantee it; a test checks the size of a scanned page). A first probe with a synthetic image gave 848 KB per page but was too compressible to be representative; measure a real scan on the iPad and then decide whether a quality setting (high, normal, small) is needed. Text recognition is out of scope (see "Out of scope"). The simulator has no camera, so it can only be checked on the iPad. Small; fits right after M6.
- **Debug overlay** (wish, 2026-10-23, to be deleted later): a small switchable panel in the editor with CPU use of the app, memory, frames per second and the thermal state (`ProcessInfo.thermalState`, the only heat signal iPadOS gives apps), to measure heat with tabs, brushes and big PDFs. **GPU use cannot be shown:** iPadOS has no public API for it (Xcode's Instruments can measure it while the iPad is connected). Keep it behind one setting and in its own folder so it can be removed in one step.
- **Known small bugs, not urgent** (developer, 2026-10-23: "I can live with it"):
  - **Undo flickers a little** on pages with translucent ink (filled shapes, highlighter). Undo and redo still swap in a fresh canvas (see "Undo bug" and "Undo flicker fixed"), and PencilKit reports "rendered" a moment before the ink is really on screen. Ideas: a longer grace period while the new canvas waits at opacity 0.01 (cheap now, because a stroke that starts finishes the swap at once), or find a way to reset PencilKit's own copy of the strokes so undo needs no swap at all (the swap-free path already works for adding shapes).
  - **Triangles on rotated pages** point sideways on screen (see "M7a, shape tool").
- **Zoom window** for writing small text (like Goodnotes' zoom box).
- **Audio recording** synced to the ink: tap a stroke to play from that moment. Feasible because `PKStrokePath` stores a creation date; recordings store their start time.
- **Links** between pages and notebooks.
- Horizontal page-by-page scrolling as an option.
- More templates (Cornell notes, music staves) and custom templates from a PDF.
- (A custom pen toolbar is now Milestone 7a.)
- Presentation mode with a laser pointer.

2. **M1, minimum iPadOS**: which iPadOS version runs on the developer's iPad? Default: the current major version minus one, but at least 17.5 (squeeze).
3. **M2, tool picker**: start with the system `PKToolPicker` (all tools for free, less control over the look). Default: yes; a custom toolbar is under "Later".
4. **M6, export method**: (a) a `PDFAnnotation` subclass that draws each page's ink, written with `PDFDocument.write`, or (b) re-render every page with `UIGraphicsPDFRenderer`: the PDF page as vector, the ink as an image at 3× scale or more. Decide after testing both with a real lecture PDF (quality, file size, how it looks in Obsidian).

Decided:
- **M1, app language:** English only (no localization).
- **M1, minimum iPadOS:** 27.0 (the developer's iPad runs iPadOS 27; this is also Xcode 27's default target).
- **M1, Swift language mode:** Swift 6 (`SWIFT_VERSION = 6.0`). The project uses Xcode's default main-actor isolation, so file and model code that must run off the main thread is marked `nonisolated`.
- **M1, Info.plist:** a real `BetterNotes/Info.plist` (next to the `.xcodeproj`, outside the synchronized source folder) is merged with the generated one. It declares Files-app sharing, the `com.anvu.BetterNotes.inkbook` package type and PDF document types. Multiple windows are enabled with the build setting `INFOPLIST_KEY_UIApplicationSupportsMultipleScenes`.
- **M1, command line builds:** `xcode-select` points at the Command Line Tools, so use `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild ...`.
- **M2 spike, cancelling a stroke (2026-10-22, iPad with Apple Pencil): the live variant works.** A `UIGestureRecognizer` subclass that only listens (never recognizes, `state = .failed` on touch end) ran alongside PencilKit with a delegate returning `true` for `shouldRecognizeSimultaneouslyWith`. After 0.5 s with less than 4 pt of movement it toggled `canvas.drawingGestureRecognizer.isEnabled` to `false` and back to `true`. The half stroke disappeared cleanly: no flicker, no leftover ink, nothing committed to the drawing. M7 builds the live variant, not the fallback. Not yet checked: whether the Pencil can keep drawing right away after the cancel while still down (M7 draws the shape in the preview layer instead, so it does not depend on this). Also: a `PKCanvasView` must use `overrideUserInterfaceStyle = .light`, otherwise a black pen is drawn white on the white page in dark mode.
- **M2, overlay geometry (measured in the simulator with a real `PDFView` in a window):** the overlay PDFKit gives a page, and so its `PKCanvasView`, is always the size of the page in PDF points (595 x 842 for A4), at every zoom (1.4x, 2.7x, 5x). PDFKit enlarges it from outside. So ink coordinates are **page points, independent of zoom, origin at the top-left of the page, y pointing down** (UIKit view convention). PDFKit's own page coordinates (and SPEC's "File format" for objects) have the origin at the bottom-left with y up; the page renderer and the export flip y with `y' = pageHeight - y`. Milestone 2 step 5 turns this into the single tested conversion.
- **M2, canvas sharpness (measured, simulator, ~5x zoom):** `PKCanvasView` ignores `contentScaleFactor`; it draws ink at the resolution of its scroll view's `zoomScale`, and PDFKit enlarges the overlay from outside, so ink looked soft (edge softness 5.3 px). Fix: each visible canvas is made `k` times bigger (`bounds` x k), given `zoomScale = k`, and shrunk back with a `1/k` transform, where `k = min(max(1, ceil(pdfZoom)), 6)`. Edge softness drops to 1.3 px. Drawing coordinates stay in unzoomed page points; a stroke drawn while zoomed landed within 2 px of the touch points. The cap of 6 equals PDFView's maximum zoom; watch memory and heat on the iPad.
- **M2, tool picker appearance:** the picker follows the system appearance (the developer prefers the dark picker). Known quirk: in dark mode PencilKit shows its default black swatch as white while the ink on the white page is black. Forcing the picker to light (`toolPicker.overrideUserInterfaceStyle = .light`) removes the mismatch; offer it as a setting if it bothers the developer.
- **M2, coordinates and renderer:** `PageGeometry` is the single place for conversions: page coordinates (top-left origin, y down, in points; what ink, objects and shapes use) <-> PDF coordinates (bottom-left origin, y up, shifted by the display box's origin) <-> view coordinates (zoom and page offset). It is tested, and checked against a real `PDFView` at zooms 1, 2 and 4. `PageRenderer.render(page:drawing:scale:)` is the single page renderer (white page, PDF vector content, then ink; objects will go between in M8). `PKDrawing.image` adapts black ink to the current appearance, so the renderer always renders in the light appearance (a test fails if this is removed). Not yet verified: imported PDFs whose crop box does not start at (0, 0), and rotated pages; check both in M3 and M4.
- **M2, autosave:** `Notebook.saveChanges()` writes every changed page's drawing atomically on a background thread, then updates `meta.json` (`updatedAt`). It runs about 2 s after the last change (`autosaveDelay`), when a page's canvas leaves the screen, when the app leaves the foreground (with a background-task assertion), and when the notebook closes. Each page has a revision counter so a stroke added during a save is not marked as saved. A failed save keeps the page marked as changed, shows a banner with Retry, and the notebook refuses to close. A drawing file that cannot be read is copied to `<id>.drawing.unreadable` before it is replaced. `OpenNotebookRegistry` refuses to open the same notebook in two windows (bringing the existing window forward is M9). Loaded drawings stay in memory after their canvas is dropped; evicting saved, off-screen drawings is part of the M3 lazy-loading tuning.
- **M2, found by a force-quit UI test:** ink that was saved correctly did not show after reopening a notebook. Cause: the editor assigned the drawing to the canvas first and magnified the canvas (`zoomScale = k`, see "canvas sharpness") afterwards, and PencilKit does not redraw a drawing set before that change. Rule: a canvas gets its final size and zoom **before** it gets its drawing (`EditorCoordinator.overlayDidAppear`); a unit test with a spy delegate pins the order. Lesson: unit tests on the model were green while the real editor lost the ink, so keep an end-to-end check (draw, close or force-quit, reopen) for every change to canvas setup.
- **M2, heat safeguard:** `EditorCoordinator` watches `ProcessInfo.thermalState`. Canvas render scale is capped at 6 (nominal, fair), 2 (serious) and 1 (critical), applied to visible canvases at once and to pages that scroll in later, and restored when the iPad cools down. It is quiet (no message). Not yet measured on the iPad: whether the app gets warm at all; the developer will report after normal use. Future background work (thumbnails in M4, export in M6) should also pause or slow down at `.serious`.
- **Milestone 2 done (2026-10-22).** All six steps built; 81 unit tests pass (about 30 s) on the iPad Air 11-inch (M2) simulator. Device results from the developer's iPad: writing with the Pencil, finger scroll and zoom, palm rejection, undo, scrolling and the tool picker work; ink survives force-quit and reopen. Not yet confirmed on the device: ink sharpness after the zoomScale fix (the first fix did nothing; the second measured 1.3 px edge softness in the simulator) and whether the iPad gets warm (heat safeguard is in, see above). Temporary pieces to replace: the flat library list with "New Notebook" (M5), the `.pencilOnly`/`.anyInput` simulator switch is permanent. Known gaps: an unreadable drawing file shows a blank page without a message (the file is kept as `<id>.drawing.unreadable` on the next save); loaded drawings stay in memory (M3 tuning); two-finger tap undo and three-finger tap redo come in M7.
- **M3, import:** `NotebookPackage.importPDF` copies the PDF to `document.pdf` (the original is never touched) into a hidden staging folder, then renames it into place. The title is the file name without `.pdf`; the notebook opens at once (several PDFs: the last one opens). Password-protected, unreadable and zero-page PDFs are refused with a message and leave nothing behind. Entry points, all through `WindowSession.importPDFs`: the Files picker (`.fileImporter`), "Open in" and Files "Share" (`.onOpenURL` in `RootView`; imports into the window that received it, closing the open notebook there first), and drag and drop onto the library (`.onDrop(of: [.pdf])`). Window routing for "Open in" is M9.
- **M3, drag and drop (found on the iPad):** `dropDestination(for: URL.self)` did not work with Files. `onDrop` plus `loadFileRepresentation` does, but the temporary file is deleted when the callback returns, so it is copied at once into our own temp folder (keeping its name) and imported from there. A SwiftUI `List` swallowed drops inside its own area (the navigation bar accepted them, the rows did not), so the library list is a `ScrollView` with `LazyVStack`; build the M5 grid the same way and attach the drop handler to the scroll view.
- **M3, rotated and cropped PDF pages (measured in the simulator with a real `PDFView`):** `PDFPage.bounds(for:)` returns the page **before** its own `/Rotate`. For a page rotated by 90 or 270 PDFKit gives the overlay the *unrotated* size (595 x 842) and **turns the overlay itself** with a transform, so ink is stored in the unrotated page space and turns with the page on screen (ink stays on the same content). Consequences: `PageMeta.size` of an imported page is the *displayed* size (width and height swapped for 90 and 270; `rotation` holds the page's own `/Rotate`); `PageGeometry` keeps working with the unrotated crop box size; `PageRenderer` makes an image of the displayed size and turns the ink layer with the page (tested for 0, 90, 180, 270). Crop boxes with a non-zero origin work without changes (overlay and render are the crop box size). Not checked on a real rotated lecture PDF on the iPad.
- **M3, search:** `DocumentSearch` uses `PDFDocument.findString` (case and diacritics insensitive) and `PDFView.highlightedSelections` (yellow; the current match orange). It runs when Return is pressed (decided against live search); Return again goes to the next match, matches wrap around. PDFView does not redraw when only the colors of the same selection objects change, so the highlights are cleared and set again on every move. Only text that is part of the PDF is searchable, never handwriting.
- **M3, memory:** `Notebook.evictDrawings(keeping:)` drops a page's drawing from memory when it is off screen, saved (not in `dirtyPageIDs`) and was read without error; it runs after the save that follows a canvas leaving the screen. Unsaved, in-flight and unreadable drawings are never dropped. The 300-page open time (target under 2 s) and scrolling feel are **not measured on the iPad** (no large PDF available); an import of a generated 300-page PDF takes well under a second in the unit tests.

- **M4, saving two files as one:** `document.pdf` and `meta.json` are replaced together through `NotebookPackage.commitStructure`: both new files go into `pending/`, an empty `COMMIT` file is written last, then the files are moved over the old ones. `Notebook.open` first calls `finishPendingCommit`: a complete `pending/` is finished, an incomplete one (no `COMMIT`) is thrown away. - **Undo bug, found on the iPad and fixed (2026-10-23):** undo a stroke, then write: the undone stroke came back. It existed since M2 (reproduced on the code of M5). Cause, measured with a UI test that draws with real touches in the simulator: after `canvas.drawing = d` on a canvas the user has drawn on, the canvas *reports* `d`, but PencilKit adds the next stroke to its own old copy of the strokes, so the undone stroke is in the next drawing it hands back. A second assignment, a fresh copy of the drawing, a real undo manager on the canvas and render scale 1 all did not help. **Fix:** when the ink of a visible page changes from outside (undo, redo), `PageOverlayView.replaceCanvas()` swaps in a fresh canvas (same delegate, tool, ruler, drawing policy; size and zoom set before the drawing, see the M2 lesson) and only then assigns the drawing. Pinned by a UI test (`UndoThenWriteUITests`, reads screenshot pixels) and a unit test for the swap. Lesson again: unit tests with a canvas that is not on screen cannot show PencilKit's behaviour; changes to canvas syncing need the end-to-end UI test.

In the simulator (no camera) the menu item shows a message. **Confirmed on the iPad (2026-10-23):** scan from the library and from the insert menu, cancel, a 10-page scan (camera closes at once). **Measured real scans:** 13 pages = 9 MB, 4 pages = 4 MB, so about **0.7 to 1 MB per page**. No quality setting for now; revisit if scanned notebooks get too big for the iPad.
- **Default pen widths (2026-10-23, developer's choice after looking at what Goodnotes users report, about 0.3-0.7 mm for text and 3-4 mm for highlighting, 1 mm = 2.8 pt):** pen and ballpoint 2, fountain pen and pencil 2.5, highlighter 12, brush and crayon 10. PencilKit's limits (measured): pen 0.88-25.7, ballpoint 0.5-4, fountain pen 1.5-14, brush 10-80, crayon 10-50, pencil 2.4-16, highlighter 7.5-60. Pens the user adjusted keep their stored width.
- **M7, decisions before building (2026-10-23):** hold to smooth comes later as **M7b** (after shapes are confirmed on the iPad); lines within 5 degrees and rectangles, ellipses and triangle bases within 8 degrees of horizontal or vertical snap to exact; a snapped shape uses the **current pen's ink** (also highlighter, pencil, fountain pen), always solid and unfilled (dashes and fill stay in the Shapes tool).
- **M7, hold to snap (built 2026-10-23; iPad check pending):** `ShapeRecognizer` (pure, tested with shaky, turned and unclosed shapes from 20 seeded "hands", and with letters, a figure eight, cursive loops, zigzags, S-curves, arcs, scribbles and a double circle that must stay nil): strokes under 15 pt are left alone; an open stroke is a line if it stays within 6 % of its length (at least 2.5 pt) of straight; a closed stroke (ends within 25 % of its size) is compared with the smallest turned box around it (rectangle), the ellipse in that box, and the biggest triangle through its outer points, and the model with the smallest average distance wins if that is under 4 % of the size and the stroke is not more than 1.35 times the model's outline (went around twice). `HoldDetector`: 0.5 s within 4 points, judged in **window points** (a still hand is still on the glass at any zoom), checked by a timer because a still Pencil may send no touches. `HoldToSnapGesture` on each overlay runs simultaneously only with PencilKit's drawing gesture, collects coalesced points, and begins only when the hold is recognized as a shape; then the coordinator switches the drawing gesture off (the M2 spike: the half stroke vanishes) until lift, shows the shape in the preview layer, and the shape follows the Pencil (`SnappedShape.following`: a line's end follows and still snaps; other shapes resize in their own turned frame from the side opposite the held point, never flipping). On lift the shape is committed through the shape tool's add-only path (one undo step "Shape", no canvas swap). **Ink look, measured from saved strokes in the simulator:** PencilKit's point size is not the tool width (highlighter 20 -> 13.3, pencil 6 -> 1.94), pencil and brush points are see-through (0.39, 0.17), and the pen's thickness comes from pressure the simulator lacks; so a snapped shape **copies the median point (size, opacity, pressure, tilt) of the last stroke drawn with the same pen and width** since the notebook opened (`InkTemplate`), with a measured table only before that. Setting: "Hold to snap shapes" in the toolbar settings (on by default). Not done yet: real handwriting samples as test fixtures (the thresholds are tuned on generated strokes), a UI test for snapping (left to the iPad check at the developer's request: things the simulator reproduces badly are tested on the device).
- **M7, first iPad round (2026-10-23):** confirmed: snapping lines and shapes, resizing while held without scrolling, write/snap/write/undo, normal writing does not snap, zoomed in, the setting off. **Fixed:** fountain pen snaps showed a preview but no result. Measured with offscreen renders: pen, ballpoint and fountain pen draw nothing for a point size of 2 or less, at any pressure or tilt, and the copied median of a thin fountain pen's stroke fell under that; those inks now never go below size 2.5 (`InkTemplate.minimumPenSize`, about 1 pt drawn). Preview tints matched by eye: highlighter stronger (0.6), pencil lighter (0.5).

## Milestones

### Milestone 0: Setup (done by the developer, not the AI)

### Milestone 2: A notebook you can write in (foundation)
